# Vladan Toolkit

Personal all-in-one desktop app for macOS, Windows and Linux. The shell (window chrome,
sidebar, ⌘K palette, settings, updates) is done; features are added one **tool** at a time.

## Stack

- **Tauri 2** (Rust backend, system webview) · **React 19** with **React Compiler 1.0** ·
  **TypeScript 7** · **Vite 8** · **Tailwind CSS 4** · **Base UI** primitives · **cmdk-base** palette
- **TanStack Router** (hash history) · **Zustand** stores (persisted to localStorage)
- Rust → TS bindings generated by **tauri-specta** into `src/bindings.ts` (never edit by hand)
- **pnpm 12** (refuses packages published <24h ago; install scripts denied by default)

## Commands

```sh
pnpm dev                 # run the desktop app (Vite + Tauri, hot reload)
pnpm dev:web             # frontend only, in a browser (Tauri APIs fall back gracefully)
pnpm new:tool <id> [--name "Name"] [--rust]   # scaffold a tool (see below)
pnpm bindings            # regenerate src/bindings.ts after changing Rust commands
pnpm check               # lint + typecheck + all JS tests + clippy + Rust tests
pnpm test                # Vitest: `unit` (jsdom) + `browser` (real Chromium) projects
pnpm test:coverage       # same, with coverage thresholds (95/90/95/95)
pnpm test:e2e            # Playwright against the production build, incl. axe WCAG 2.2 AA scans
pnpm e2e:native:build && pnpm e2e:native   # drive the real compiled app via WebDriver
pnpm lint:rust / test:rust
```

Browser tests need Chromium: `pnpm playwright install chromium`, or point `CHROMIUM_PATH`
at an existing binary.

## Layout

```
src/
  app/            shell: router, AppShell, TitleBar, Sidebar, CommandPalette, pages
  core/           tool registry, IPC, hotkeys, theme, stores, updater (framework-agnostic logic)
  components/ui/  primitives (Button, Kbd, Switch, Segmented, Tooltip, Section/Row)
  tools/<id>/     one folder per tool, auto-discovered
  bindings.ts     GENERATED from Rust
  styles/         design tokens (globals.css)
src-tauri/
  src/lib.rs      builder, plugins, setup, command registry (`specta_builder`)
  src/commands/   shell commands (app_info)
  src/tools/      one Rust module per tool that needs native code
  capabilities/   permission allow-list for the webview (least privilege)
e2e/web/          Playwright specs (Chromium ≈ WebView2, WebKit ≈ WKWebView/WebKitGTK)
e2e/native/       WebdriverIO specs against the real app (own tsconfig)
scripts/          tool generator, CI helpers (tested)
```

## Adding a tool

1. `pnpm new:tool json-formatter --name "JSON Formatter"` (add `--rust` if it needs native code).
   Creates `src/tools/json-formatter/{index.ts,JsonFormatter.tsx,JsonFormatter.test.tsx}`.
   That's all it takes to register it: sidebar, home, ⌘K and ⌘1 to ⌘9 pick it up automatically.
2. Edit `index.ts`: a real `description`, a lucide `icon`, `keywords`, optional `order`,
   `layout: 'full'` for editor-like tools, and `commands` to add ⌘K actions.
3. Native code (`--rust`): the generator adds `src-tauri/src/tools/<snake>.rs` and registers
   it (markers `// new-tool:modules` / `// new-tool:commands`; keep them). Annotate commands
   with `#[tauri::command]` + `#[specta::specta]`, derive `specta::Type` on returned structs,
   then run `pnpm bindings` and call `commands.xxx()` from `@/core/ipc`.
   - Avoid `u64`/`i64` in returned types (TS can't represent them): use `f64` or `u32`.
   - Guard native calls with `isTauri()` and give the browser preview a sensible fallback.
   - New plugin or OS access? Add the narrowest permission to `src-tauri/capabilities/default.json`.
4. Tests: logic in `*.test.ts` (jsdom), UI in `*.test.tsx` (real browser), Rust `#[cfg(test)]`.
   Mock Tauri with `mockTauri()` from `src/test/tauri.ts`.

The System Info tool (`src/tools/system-info`, `src-tauri/src/tools/system_info.rs`) is the
reference implementation of a Rust-backed tool.

## Conventions

- **Design**: dark-first, minimal. Use the semantic tokens only (`bg-canvas`, `bg-surface`,
  `text-fg-muted`, `border-line`, `bg-accent`, `text-accent-text`, …), never raw colors. Every
  pairing must stay ≥ 4.5:1; the axe E2E scans fail otherwise. Desktop density: 13px base.
- **Writing**: no em dashes, en dashes or spaced hyphens as punctuation in docs, comments,
  UI text, commit messages or PR text. Use a period, comma, colon or parentheses instead.
  `pnpm lint:dashes` enforces it for files (pre-commit, pre-push and CI).
- **Accessibility**: real roles/labels; shortcuts via `aria-keyshortcuts` with decorative `<Kbd>`.
- **TypeScript**: strict, no `any`, no non-null `!`. Biome formats and lints (`pnpm lint:fix`).
- **Rust**: `unsafe` is forbidden; clippy pedantic with `-D warnings`; no `unwrap`/`expect`
  outside tests.
- **Commits**: Conventional Commits (enforced by commitlint and the PR-title check). They drive
  releases: `fix:` → patch, `feat:` → minor, `feat!:`/`BREAKING CHANGE:` → major.
- Don't hand-edit `src/bindings.ts`, `CHANGELOG.md`, versions, or `.release-please-manifest.json`.

## Testing gotchas

- Vitest 5 browser mode: `toHaveTextContent` is an **exact** match; use `toMatchTextContent`
  for substrings. Locator `name`/text strings are exact too; use a RegExp for partial matches.
- Popups (tooltips, dialogs) render in portals outside the render container: query them with
  `page` from `vitest/browser`, not the `screen` returned by `render`.
- In `userEvent.keyboard`, `[` and `{` are special: write `[[` / `{{`.
- Coverage runs with `REACT_COMPILER=off` so compiler-generated memo branches don't count;
  `pnpm test` and all E2E run the compiler.

## CI/CD (all automatic)

- **CI** (`ci.yml`), kept lean on purpose: one `web` job (lint, typecheck, secret scan, dash
  check, commitlint, unit+component tests with coverage, Playwright in Chromium+WebKit) and one
  `desktop` job per OS (clippy, Rust tests with ≥80% coverage on Linux, native E2E), each
  compiling Rust once. Installers build only for releases, or on demand via "Run workflow".
  `CI OK` is the single required check. Don't add jobs when a step in an existing job will do.
- **Security**: CodeQL (actions, JS/TS, Rust), dependency review, pnpm audit, cargo-deny,
  zizmor, OpenSSF Scorecard, Dependabot (7-day cooldown, auto-merge for patch/minor).
- **Release** (`release.yml`): release-please keeps a release PR up to date; merging it
  tags a draft release, builds signed installers + updater bundles on macOS/Windows/Linux with
  SLSA provenance, then publishes. Installed apps pick it up through the updater.
- Actions are pinned by commit SHA (Dependabot updates them); local actions use `$/` syntax.
